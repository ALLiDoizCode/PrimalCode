# Story 1.3: Core Ecosystem Observation MCP Tools

## Status
Approved

## Story

**As a** player,
**I want** to observe monster behaviors and ecosystem states through natural language commands,
**so that** I can understand the autonomous ecosystem and plan environmental modifications.

## Acceptance Criteria

1. "observe_ecosystem" MCP tool providing natural language descriptions of current ecosystem state
2. "analyze_monster" MCP tool giving detailed behavioral analysis for individual creatures
3. "check_environment" MCP tool describing current environmental conditions and modifications
4. Rich, engaging text descriptions that make autonomous creatures feel alive and interesting
5. Consistent response format with current state, interesting observations, and suggested actions

## Dev Notes

### Previous Story Insights
From Story 1.2: Mock monster data system is fully implemented with 3 personality types (Aggressive Hunter, Cautious Forager, Pack Leader), realistic behavior simulation, and time-based state updates. The mock environment state system includes weather conditions, resources, and ecosystem balance tracking. Both systems are located in `src/ecosystem/` directory and provide comprehensive APIs for querying monster and environment states.

### Data Models
[Source: architecture/data-models.md#monster]
- **Monster Interface**: Must access id, species, stats (health, hunger, energy, position), ai_personality (aggression, intelligence, pack_tendency), environmental_awareness, and state
- **Monster Position**: Must include x, y coordinates and route string for location descriptions
- **Monster Environmental Awareness**: Must access detected_structures, resource_memory arrays, and weather_adaptation values

[Source: architecture/data-models.md#environment]
- **Environment Interface**: Must access route_id, structures, resources, weather_state, ecosystem_balance, and last_modified timestamp
- **Environmental Structures**: Must access player modifications and their current states
- **Resource Pools**: Must access food, water, and scent marker information for environment descriptions

### API Specifications
[Source: architecture/api-specification.md#mcp-tool-specification]
- **Ecosystem Observer Tool Schema**:
  ```typescript
  {
    name: "observe_ecosystem",
    description: "Get detailed natural language description of current ecosystem state",
    inputSchema: {
      type: "object",
      properties: {
        route_id: { type: "string", description: "Route/habitat to observe" },
        focus: { type: "string", description: "Specific aspect to focus on (monsters, environment, interactions)" }
      },
      required: ["route_id"]
    }
  }
  ```
- **Monster Analyzer Tool Schema**: Must accept monster_id and analysis_depth parameters
- **Environment Checker Tool Schema**: Must accept route_id parameter for environment queries

### Component Architecture
[Source: architecture/components.md#fastmcp-server]
- **FastMCP Server**: MCP tools must integrate with FastMCP Protocol endpoints and provide proper error handling
- **Environment Manager**: Tools must query environmental state through established interfaces
- **Monster AI Engine**: Tools must access monster decision-making data for behavioral insights

- **MCP Framework**: FastMCP Latest for MCP tool implementation
- **Testing**: Jest 29+ for unit testing with TypeScript support

- **Integration**: Must integrate with mock monster system and mock environment state from Story 1.2

### Coding Standards Requirements
[Source: architecture/coding-standards.md]
- **Type Safety**: All MCP tool interfaces must be properly defined in TypeScript
- **Error Handling**: Comprehensive error handling with user-friendly messages for all tools
- **Natural Language**: All tool responses must be engaging and narrative-driven descriptions
- **Naming Conventions**: 
  - MCP Tools: snake_case (e.g., `observe_ecosystem`, `analyze_monster`, `check_environment`)
  - Functions: camelCase (e.g., `generateEcosystemDescription`, `analyzeMonsterBehavior`)
  - Types: PascalCase (e.g., `EcosystemObservation`, `MonsterAnalysis`)
  - Constants: UPPER_SNAKE_CASE (e.g., `DEFAULT_ANALYSIS_DEPTH`)

### Project Structure Notes
The story requirements align perfectly with the unified project structure. The `src/tools/` directory is specifically designed for MCP tool implementations, which matches all three required tools. The integration with existing mock systems in `src/ecosystem/` follows established patterns from Story 1.2.

### Test Example Pattern
[Source: architecture/testing-strategy.md#mcp-tool-test]
```typescript
describe('EcosystemObserver', () => {
  let tool: EcosystemObserverTool;
  let mockMonsterSystem: jest.Mocked<MockMonsterSystem>;
  let mockEnvironmentState: jest.Mocked<MockEnvironmentState>;
  
  beforeEach(() => {
    mockMonsterSystem = createMockMonsterSystem();
    mockEnvironmentState = createMockEnvironmentState();
    tool = new EcosystemObserverTool(mockMonsterSystem, mockEnvironmentState);
  });
  
  it('should generate engaging ecosystem description', async () => {
    // Arrange
    const mockEnvironment = createMockEnvironment();
    const mockMonsters = createMockMonsters();
    mockEnvironmentState.getEnvironmentState.mockResolvedValue(mockEnvironment);
    mockMonsterSystem.getMonstersInRoute.mockResolvedValue(mockMonsters);
    
    // Act
    const result = await tool.execute({ route_id: 'forest_path' });
    
    // Assert
    expect(result.currentState).toContain('forest path');
    expect(result.monsterBehaviors).toHaveLength(mockMonsters.length);
    expect(result.suggestedActions).toBeInstanceOf(Array);
  });
});
```
