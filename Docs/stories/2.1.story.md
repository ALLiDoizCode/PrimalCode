- **AI Personality**: Must include aggression, intelligence, pack_tendency as numerical values for decision-making
- **Environmental Awareness**: Must track detected_structures array, resource_memory array, and weather_adaptation value
- **Influence Resistance**: Must include learned_patterns record and adaptation_history array for learning

### AO Process State Schema
[Source: architecture/database-schema.md#ao-process-state-schema]

- **State Persistence**: All state variables must be stored in AO process memory with automatic Arweave backup
- **State Updates**: Must support atomic state updates with proper validation

### API Specifications
[Source: architecture/api-specification.md#ao-message-schemas]

- **Get-State Message**: Must respond to state queries with current monster state

### Component Architecture

- **Environment Manager**: Must manage route-level environmental state and player modifications through environmental modification processing, weather system and timing control, resource management and decay, and ecosystem balance monitoring

### Coding Standards Requirements
[Source: architecture/coding-standards.md]
- **AO Process Naming**: Functions must use snake_case (e.g., `make_decision`, `update_state`)
- **Types**: Must use snake_case for AO process types (e.g., `monster_state`, `ai_personality`)
- **Constants**: Must use UPPER_SNAKE_CASE (e.g., `DECISION_INTERVAL`, `MAX_HEALTH`)
- **Variables**: Must use snake_case (e.g., `monster_id`, `current_state`)
- **AO Messages**: Must use kebab-case (e.g., `Environment-Change`, `Monster-Communication`)
- **State Consistency**: AO process state updates must be atomic and include rollback mechanisms
- **Autonomous Integrity**: Monster decisions must never be directly controlled by players
- **Performance Budgets**: AI API calls must complete within 5 seconds or fall back to cached decisions

### Core Workflows
[Source: architecture/core-workflows.md#monster-decision-making-workflow]
- **Monster Decision-Making Workflow**: Must follow the established pattern of decision timer triggers (30-60s), environmental state queries, nearby monster scanning, AI decision requests with context, decision caching and Claude API integration with fallback to rule-based systems, decision execution with state updates, and broadcasting of relevant state changes to other monsters and environment
- **Decision Flow Integration**: Must implement Monster Process → AI Engine → Claude API → Decision Cache → Rule-based Fallback workflow with proper error handling and graceful degradation
- **State Synchronization**: All monster processes must properly synchronize state changes with environment and other monster processes for consistent ecosystem state

[Source: architecture/core-workflows.md#environmental-modification-workflow]
- **Environmental Modification Response**: Monster processes must respond to environmental modifications through the established workflow of receiving environment change broadcasts, adapting behavior to changes, learning modification patterns, and reacting to environmental cues
- **Ongoing Adaptation**: Must implement continuous adaptation to environmental modifications with behavioral learning and pattern recognition

### Testing Standards
[Source: architecture/testing-strategy.md#ao-process-test]
- **Test File Structure**: Create `tests/unit/ao-processes/monster-process.test.lua` following AO process testing patterns
- **Test Framework**: Use Lua testing framework with describe/it pattern for AO process tests
- **Test Example Pattern**:
  ```lua
  -- Monster Process Test
  local monster = require('./monster-process')
  
  describe("Monster Decision Making", function()
    it("should make hunting decision when hungry", function()
      -- Arrange
      local test_monster = {
        stats = { hunger = 80, energy = 60, health = 100 },
        ai_personality = { aggression = 0.7 },
        environmental_awareness = { detected_prey = {"small_creature"} }
      }
      
      -- Act
      local decision = monster.make_decision(test_monster)
      
      -- Assert
      assert.equal(decision.action, "hunt")
      assert.equal(decision.target, "small_creature")
    end)
  end)
  ```

### AO Process Integration Points
