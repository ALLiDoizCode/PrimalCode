### Technical Architecture Context
**Project Structure Requirements** [Source: architecture.md#source-tree]:
- Monorepo structure with separate directories for each AO process type
- `ao-processes/` containing world, battle, registry, and health-monitor processes
- `shared/` directory for common utilities and types
- `scripts/` for build and deployment automation
- `tests/` with unit, integration, and mock-agents directories
- `development/` for monitoring and debugging tools

**Technology Stack** [Source: architecture.md#tech-stack]:
- Primary Language: Lua 5.3+ for AO process handler implementation
- Process Runtime: AO (Arweave Operating System) - Latest
- Local Development: aolite - Latest for AO process testing framework
- AI Code Generation: Permamind MCP Server - Latest for Lua process generation
- Development Tools: Claude Code + MCP - Latest for AI-assisted development
- Testing Framework: aolite + Custom Test Harness - Latest for unit and integration testing
- Deployment: Arweave Network - Native process deployment and hosting

**Development Environment Requirements** [Source: architecture.md#infrastructure-and-deployment]:
- Development: Local aolite simulation environment for rapid iteration
- Testing: Dedicated AO testnet processes for integration validation
- Production: Mainnet AO processes for live agent interactions
- Environment Promotion Flow: Local aolite → Testnet AO → Mainnet AO

**Coding Standards** [Source: architecture.md#coding-standards]:
- Languages & Runtimes: Lua 5.3+ for AO processes, JavaScript for tooling and tests
- Style & Linting: Teal type checking for Lua code, ESLint for JavaScript components
- Test Organization: `*.test.tl` for Lua tests, `*.test.js` for JavaScript integration tests

**Security Requirements** [Source: architecture.md#security]:
- All external message handlers must validate against ADP v1.0 specification
- Deterministic random generation required using seeded RNG
- No hardcoded process IDs or agent identifiers
- Configuration via process initialization messages only

### Testing Standards
**Test File Locations** [Source: architecture.md#coding-standards]:
- `*.test.tl` for Lua AO process unit tests
- `*.test.js` for JavaScript integration tests
- Unit tests in `tests/unit/` directory structure
- Integration tests in `tests/integration/` directory
- Mock agents in `tests/mock-agents/` directory

**Testing Framework Requirements** [Source: architecture.md#tech-stack]:
- aolite testing framework for AO process validation
- Custom test harness for AO process handler testing
- Mock external agents for integration testing
- JavaScript-based integration tests for cross-process workflows

**Testing Patterns** [Source: architecture.md#coding-standards]:
- All AO processes must have corresponding unit tests
- Integration tests must validate inter-process message passing
- Mock agents must simulate external agent behavior patterns
- Test data must use deterministic seeded random generation
